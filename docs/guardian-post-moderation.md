# Experimental Instant Public (staged, not activated)
The third selector is available for local preview preference only. Live databases without the staged migration reject it. Production remains Instant Private. The experimental path is limited to short new plain text with no attachments/contact/link-like strings; all enabled fast rules must pass and a fresh worker heartbeat, active AI/link/flood switches and a nonempty enabled custom-word list are required. The existing exact-text pre-approval remains mandatory for everything else. The frontend falls back only on the explicit preapproval-required error, using the same ID and never retrying unknown errors. A committed queue job is required for every deferred decision. Worker claims only database messages with restricted service RPCs; a separate watchdog removes expired unchecked messages by fingerprint. No guarantee that a recipient has not seen or captured a message. If scheduler and worker both fail, already published content may remain visible until recovery. Do not activate for students until isolated tests validate worker outage, cron scheduling, auth, deletion realtime, retries, edits, disabled switches, direct inserts and quotas; review privacy notice and moderation policy. The worker requires a dedicated high-entropy secret in Edge secrets and Vault, never committed. No production migration, scheduling, deployment, or extra cost authorized by this PR. Instant Private is recommended.
